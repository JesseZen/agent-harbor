# Agent Harbor 接入 Antigravity CLI（agy）的可行性

2026-11-19 · Harbor `main` 基线 `ad00eea`。范围是 Google Antigravity CLI `agy` 在 Herdr 中的原生连接、对话恢复、Profile 和可选 Magpie 连接。

## 结论

**先支持已有环境中的原生 `agy`。** Google 已提供按对话 ID 恢复的 CLI 参数，Herdr 已提供 `agy` 的识别、状态检测、对话 hook 和恢复命令生成。相较 Claude Code，Harbor 额外要解决集成名 `antigravity_cli` 与客户端名和程序名 `agy` 不同的问题。两者可以共用启动、Profile 绑定、观察和恢复复核。Claude Code 已有真实客户端续接上下文的历史验收，agy 目前有 Herdr 恢复参数的历史验收和本轮的 CLI 参数验证。 [Google CLI 参数](https://antigravity.google/docs/cli/reference/#command-line-flags)、[Herdr 集成](https://herdr.dev/tui/docs/integrations/#antigravity-cli)、[Harbor 发现](../../bridge/capabilities.go#L97)、[候选恢复测试](../herdr-resume-command.patch)、[现有真实第二客户端测试](../../bridge/tests/second_client_real.py)

**独立 Profile 和 Magpie 是两项能力。** Google 的 CLI 使用系统凭据库，`--settings` 只覆盖这次运行的设置，完整的配置、历史和登录隔离还需要证据。Magpie 连接有一条清晰的上游试验路径：用 Google 的进程级网关配置接 Magpie 已有协议。新版 Magpie 也把 agy 的模型配置移到了自己的覆盖文件。两条路径都要证明确实按会话固定实例和模型。 [Google 认证](https://antigravity.google/docs/install?tab=cli#local-silent-keyring-sign-in)、[Google 网关配置](https://docs.cloud.google.com/gemini/enterprise/docs/ai-developer-tools/connect-enterprise-gateway#custom-environments)、[Magpie v0.1.4499](https://github.com/yetone/magpie/blob/v0.1.4499/internal/agent/agy.go#L16-L24)

## Magpie 应优先试哪条上游路径

1. **先试 Google 官方的进程级网关接口。** `agy` 1.2.15 起可用 `AGY_LLM_GATEWAY_URL`、`AGY_LLM_GATEWAY_API_KEY`、`AGY_LLM_GATEWAY_WIRE_PROTOCOL` 和可选模型清单指定网关。Google 文档要求 HTTPS，组织 `admin_settings.json` 优先。Magpie 已提供 Gemini 和 OpenAI Chat Completions 路由，当前固定版也有 Antigravity 格式模型目录。拿一套上游协议做联调，检查现有 Magpie 地址能否直接使用，或需要经验证的 HTTPS 入口，并核对模型 ID、认证头、流式工具回路和失败行为。若成立，Harbor 只在该会话进程注入已验证的连接参数，并将 Herdr 的恢复 argv 原样接入。 [Google 客户端配置](https://docs.cloud.google.com/gemini/enterprise/docs/ai-developer-tools/connect-enterprise-gateway#custom-environments)、[Google 网关协议](https://docs.cloud.google.com/gemini/enterprise/docs/ai-developer-tools/deploy-enterprise-gateway)、[固定版 Magpie 路由](https://github.com/yetone/magpie/blob/5426c43cca9b90be809d51edebc5c926929e9f6c/internal/gateway/gateway.go#L1061-L1073)、[固定版 Magpie 模型目录](https://github.com/yetone/magpie/blob/5426c43cca9b90be809d51edebc5c926929e9f6c/internal/gateway/gateway.go#L1610-L1615)
2. **也有 Magpie 的原生 agy 启动入口。** Harbor 当前固定的 `0.1.3528` 用共享 agy settings 选择 Gemini API 模式、模型和自定义目录，`magpie agy run` 读取这份选择，再给进程传 `GEMINI_API_KEY`、`GOOGLE_GEMINI_BASE_URL` 和 `--model`。未选中 Magpie 模型时 launcher 会直接启动客户端。上游 `v0.1.4499` 已改用独立的 `magpie-settings.json`，以 `agy --settings <file>` 传入模型配置，并保留常规启动走原设置。其作用域仍是同一个 CLI home，源码还记录了 `/model` 可能写入原 `settings.json`。若需要这条路径，优先验证升级后的公开启动接口是否能按次指定绑定的 Magpie 实例、模型和覆盖文件，允许同时开 A、B 路由和一个原生会话。缺少该契约时把需求交给上游。升级需要验证 Harbor 现有 Codex 补丁及 ZCode 依赖。 [Google Gemini API 连接](https://antigravity.google/docs/install?tab=cli#using-a-gemini-api-key)、[固定版 Magpie launcher](https://github.com/yetone/magpie/blob/5426c43cca9b90be809d51edebc5c926929e9f6c/internal/cli/agy_cli.go#L69-L95)、[新版 launcher 配置与写回](https://github.com/yetone/magpie/blob/v0.1.4499/internal/agent/agy.go#L222-L296)、[Magpie 文档](https://usemagpie.ai/docs/antigravity#the-agy-cli)、[Harbor 打包依赖与补丁](../magpie-caller-integration.md)
3. **连接归属由实际认证决定。** agy 通过 Magpie 请求模型时，CLI 用的是网关凭据。Google Enterprise Gateway 模式与 Google 登录互斥。Magpie 把 Antigravity 账号作为上游供应商是另一条链路，凭据、配额和路由由 Magpie 自己管理。Harbor 对 agy 的首个网关验收适合使用 Magpie 配置的 API 供应商，并按需再验证路由组。当前 Harbor 对非 Codex 的 Magpie 创建和执行已有明确限制，需要单独接入这一能力。 [Google 网关认证和计费](https://docs.cloud.google.com/gemini/enterprise/docs/ai-developer-tools/connect-enterprise-gateway)、[Magpie 供应商说明](https://usemagpie.ai/docs/antigravity#your-google-sign-in)、[Harbor 创建](../../bridge/service.go#L198)、[Harbor 执行](../../bridge/launch.go#L55)

## 实现后的体验与验证范围

- 用户只安装 agy 也能打开 Harbor。在新建会话中选择项目、已有环境和 `Antigravity CLI · Native`，在 Herdr 的 agy 终端完成 Google 登录和项目授权。首个 prompt 后捕获对话 ID。再次打开时在运行就回原 pane，退出后 `Resume` 打开同一段对话。项目、历史、登录或连接证据有缺口时展示原因，留给用户确认原归属。 [Harbor 产品契约](../spec.md)、[Google 登录与对话](https://antigravity.google/docs/install?tab=cli)、[Herdr 身份捕获](https://herdr.dev/tui/docs/integrations/#antigravity-cli)
- 网关联调通过后，同一个已有环境可并行开原生 agy 和选定 Magpie 实例、模型的 agy。恢复应保留当时的连接，实例不可用或被替换时进入复核。原生登录留在 Google 客户端，网关会话使用 Magpie 所选供应商的实际凭据。远程 Herdr 前端断开时仍可重连在跑的 pane，服务器重建后的恢复取决于原数据和连接是否保留。 [Harbor 连接与恢复](../spec.md)、[远程工作区](../remote-workspaces.md)、[Google 网关认证](https://docs.cloud.google.com/gemini/enterprise/docs/ai-developer-tools/connect-enterprise-gateway)
- 本轮在临时 `HOME`、XDG 目录和清理后的进程环境下，验证 macOS arm64 原生 agy `1.5.11` 的 `--version`、`--help` 均成功。帮助列出了 `--conversation`、`--model` 和 `--settings`，其中 `--settings` 接受 JSON 或文件路径，描述为当次运行使用。已有 Linux 候选测试跑了实际 Herdr 二进制，查验 agy 恢复参数。真实 agy 登录、Herdr hook 上报、用原 ID 续接上下文、Profile 双账号和 Magpie 并发路由均待验收。原生验收应先覆盖仅安装 agy、首次安装 hook、捕获 ID、断线重连、退出后读到原上下文，以及缺少历史或切换对话时不会串线。 [现有恢复参数测试](../herdr-resume-command.patch)、[第二客户端验收样板](../../bridge/tests/second_client_real.py)、[隔离验收约定](../../bridge/tests/README.md)
