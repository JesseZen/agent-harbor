# Agent Harbor 接入 Claude Code 可行性

2026-11-19 · 调研基线为 `main` 的 `ad00eea`。范围是用户自行安装的交互式 Claude Code CLI，以及它在 Harbor 中的原生连接、Profile、恢复和可选 Magpie 连接。

## 结论

**Claude Code 原生连接值得先做。** 较早的开发候选在 Linux amd64 和 macOS arm64 上用真实的 Claude Code 2.1.322 和 Herdr 验证了启动、捕获对话 ID、退出和按原 ID 恢复。模拟 Anthropic Messages 服务收到的第二轮请求包含首轮上下文。验收使用合成 API 凭据，并在隔离环境中预先配置工作目录信任。当前 Profile 实现中的完整流程、真实账号登录和 Claude 的 Magpie 连接仍待验收。主要改动是支持只安装 Claude 的工作区，为 Claude 绑定自己的 Profile 环境，并让恢复复核原环境、原对话和原连接。 [真实客户端验收脚本](../../bridge/tests/second_client_real.py#L109)、[Harbor 产品契约](../spec.md)

**Magpie 已有 `magpie claude run`，可以沿这条上游路径做后续验证。** Harbor 目前拒绝非 Codex 的 Magpie 会话。先验证上游 launcher 能否固定每次会话的实例和模型，并让 API 凭据与 Claude 原生订阅分别归属其官方流程。Anthropic 对第三方收集、存储或代转用户订阅凭据有明确限制。 [Harbor 创建校验](../../bridge/service.go#L198)、[Magpie launcher](https://usemagpie.ai/docs/start#agents)、[Anthropic 网关文档](https://code.claude.com/docs/en/llm-gateway)、[Anthropic 认证使用条件](https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use)

**维护边界以复用上游为准。** Claude Code 负责原生交互、登录、项目授权及历史。Herdr 负责发现客户端、提供 hook 集成、管理终端及生成恢复命令。Magpie 负责网关、模型、路由和配置启动。Harbor 只负责能力提示、Profile 与会话绑定、运行范围核对及恢复复核。Herdr 服务重启后，客户端连回时会触发上游的原生对话恢复。仅断开客户端时，原进程仍在服务端运行。Harbor 当前关闭这项自动行为，以保留对 Profile 和原连接的复核。现有命令查询来自本地通用补丁，优先推动该查询和所需证据成为上游发布接口。 [Harbor 产品契约](../spec.md)、[Herdr 原生恢复](https://herdr.dev/tui/docs/session-state/#native-agent-session-restore)、[上游命令入口](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/cli/agent.rs#L49-L61)、[Herdr 查询补丁](../herdr-integration.md)、[Magpie 上游配置机制](https://github.com/yetone/magpie/blob/5426c43cca9b90be809d51edebc5c926929e9f6c/docs/subsystems/agent-wiring.md#L38)

## 原生连接如何落地

- **保持原生终端。** 启动官方 `claude`。Anthropic `SessionStart` hook 提供 `session_id`、`cwd`、`transcript_path`，覆盖启动、恢复、清空、压缩和分支。打包依赖所用的上游 Herdr v11 hook 在 `CLAUDE_CONFIG_DIR` 中配置，通过 Python 3 解析并在匹配的 Herdr socket/pane 上报 ID、可用的 transcript 路径和 `source`，忽略子代理。应把 Python 3 缺失与客户端无法启动分开报告。用户仍在官方 CLI 确认工作目录信任；`--session-id` 可为新对话指定 UUID，参数只能作为启动意图。 [CLI 参数](https://code.claude.com/docs/en/cli-reference#cli-flags)、[SessionStart](https://code.claude.com/docs/en/hooks#sessionstart)、[Herdr 配置目录](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/integration/env.rs#L58-L62)、[Herdr hook 实现](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/integration/assets/claude/herdr-agent-state.sh#L5-L84)
- **按确切的 UUID 恢复。** 复用 Herdr 从 `id` 种类的引用生成的 `claude --resume <UUID>`。当前 Herdr 把 Claude hook 的报告归一为 ID，公开查询仍需验证恢复以外的条件。Claude CLI 自 2.1.223 起可继续搜索其他项目目录，活跃的 Claude 后台会话在新版本可被附着。因此首版限定 Harbor 托管的前台进程，并用上游可得证据核对同一 Profile、原工作目录、对话是否已保存及活动写入者。`--continue` 选择最近对话，按名称恢复有重名风险。CLI 本地历史默认保留 30 天。证据不全交给明确复核，过期或确认丢失时报告无法恢复。对话内容留在 Claude 的历史文件中。 [Herdr 引用规范](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/agent_resume.rs#L116-L132)、[Herdr 恢复参数](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/agent_resume.rs#L199-L211)、[CLI 参数](https://code.claude.com/docs/en/cli-reference#cli-flags)、[本地保留策略](https://code.claude.com/docs/en/data-usage)
- **把登录留给 Claude Code。** `CLAUDE_CONFIG_DIR` 指定用户设置、历史和插件目录。Anthropic 文档说明，Linux 凭据文件和 macOS Keychain 写失败时的回退文件都随这个目录，正常的 macOS Keychain 凭据也按配置目录区分。核验 macOS Keychain、Linux 文件和远程 SSH 下的登录实行为；同时处理环境变量及项目、组织设置对认证和端点的覆盖。对有意沿用的原生连接展示已确认的认证来源，状态无法证明原连接时要求用户复核。`claude auth status` 提供认证类型，2.1.268 起还返回 `configDirectory`，便于核对 CLI 实际使用的目录。Profile 隔离用户数据，项目文件、项目配置与组织策略仍按 Claude 自己的规则读取。 [配置目录](https://code.claude.com/docs/en/env-vars)、[认证与凭据存储](https://code.claude.com/docs/en/authentication)、[配置优先级](https://code.claude.com/docs/en/settings)、[CLI 登录命令](https://code.claude.com/docs/en/cli-reference#cli-commands)
- **保留 CLI 与程序化调用的分工。** `claude -p` 支持 JSON 或流式 JSON，能从结果取回 `session_id`，适合受控测试和批处理。官方 TypeScript/Python Agent SDK 提供按项目和 UUID 查询会话元数据的接口，可以再评估用于显式认领。自动标题可以另行验证，首版沿用项目与连接名称作回退。SDK 会引入运行时与认证要求，且 `-p` 和 SDK 的工作目录信任规则不同。首版把原生交互和权限确认留在 Herdr pane。 [非交互 CLI](https://code.claude.com/docs/en/headless)、[SDK 元数据查询](https://code.claude.com/docs/en/agent-sdk/typescript#getsessioninfo)、[SDK 运行环境](https://code.claude.com/docs/en/agent-sdk/quickstart)、[工作目录信任](https://code.claude.com/docs/en/hooks#workspace-trust)、[现有标题规则](../herdr-integration.md#session-display-names)

## Magpie 连接的额外工作

Harbor 现有创建服务、runner 和模型目录走 Codex 的 Magpie 逻辑。固定版 Magpie 已提供 `/v1/messages` 和 `/v1/messages/count_tokens`，并支持 `magpie claude run [args…]`（也可通过 `claude-magpie` 调用）。它把 Claude 作为子进程运行，生成 `--settings` 文件并把其余参数交给 Claude。可以先在验证环境试由 Harbor 传入官方 `--model` 作为新建会话的初始选择，恢复时转交 Herdr 提供的 `--resume` 参数，并按官方规则核对恢复使用的模型。 [Harbor 创建校验](../../bridge/service.go#L198)、[固定版 Magpie 路由](https://github.com/yetone/magpie/blob/5426c43cca9b90be809d51edebc5c926929e9f6c/internal/gateway/gateway.go#L1061-L1073)、[Magpie 启动实现](https://github.com/yetone/magpie/blob/5426c43cca9b90be809d51edebc5c926929e9f6c/internal/cli/claude_launch_cli.go#L75-L99)、[Claude 模型优先级](https://code.claude.com/docs/en/model-config#which-model-a-resumed-session-uses)

当前 launcher 的配置在每个 Magpie 配置目录中共享。`run` 后的参数都是 Claude 参数，未提供针对单次调用的 Magpie 实例或网关密钥参数。Claude 的 `/model` 可能写入用户 settings，Magpie 在子进程退出时回写 launcher 模型并恢复原模型。由此推断，同一 Claude 配置根运行多个会话时需要验证写入竞争、异常终止、进程控制及 hook 上报。还需核查 Magpie 对 Claude 账号的发现、读取与写入。达到按运行固定实例、模型与 API 凭据的可验证条件后再开放用户入口。若上游 launcher 做不到，先请求可按会话传入的配置能力。已有网关只设 `ANTHROPIC_BASE_URL` 时可能接收 Claude 保存的订阅凭据，所以 API 路径必须独立验证实际认证和计费来源。 [Magpie 参数](https://github.com/yetone/magpie/blob/5426c43cca9b90be809d51edebc5c926929e9f6c/internal/cli/claude_launch_cli.go#L17-L30)、[Magpie 配置文件](https://github.com/yetone/magpie/blob/5426c43cca9b90be809d51edebc5c926929e9f6c/internal/agent/claude_launch.go#L27-L94)、[Magpie 模型回写](https://github.com/yetone/magpie/blob/5426c43cca9b90be809d51edebc5c926929e9f6c/internal/agent/claude_launch.go#L117-L160)、[固定版 Magpie 账号发现](https://github.com/yetone/magpie/blob/5426c43cca9b90be809d51edebc5c926929e9f6c/internal/provider/discovery.go)、[Claude 网关认证](https://code.claude.com/docs/en/llm-gateway#subscriptions-and-gateways)

首个实际验收可用真实 Claude + 真实候选 Magpie + 用户配置的 Claude Messages 上游。接口检查至少覆盖 `/v1/messages`、顺序完整的流式 SSE、`anthropic-version` 和 `anthropic-beta` 透传、工具回路、上下文和缓存字段、错误与辅助请求；`count_tokens` 可选。网关 `/v1/models` 发现需打开客户端开关，列表仅接纳 ID 中含 `claude` 或 `anthropic` 的条目，还受组织模型限制。Harbor 可以先用自身已验证的目录显示支持的 Claude 模型，按固定模型验证再尝试仅含已验证 Claude 上游的路由组。Anthropic 文档将非 Claude 后端排在其支持范围之外。 [网关兼容规范](https://code.claude.com/docs/en/llm-gateway-protocol)、[模型配置](https://code.claude.com/docs/en/model-config)、[其他 LLM 网关](https://code.claude.com/docs/en/llm-gateway)

## 实现后用户会看到什么

1. 在 Harbor 新建会话时选择项目、Profile、`Claude Code` 和 `Native`。首次使用该 Profile 时在 Claude 官方界面完成登录和项目授权。之后直接进入 Herdr 中的 Claude Code 终端，沿用 Claude 自己的命令、权限提示、MCP 和插件规则。 [设置作用域](https://code.claude.com/docs/en/settings)、[CLI 参考](https://code.claude.com/docs/en/cli-reference)
2. 新建记录立即出现在 Harbor 列表。收到本次运行的对话报告后才具备恢复所需的身份。终端仍在就回到原 pane。会话正常退出或完成停机复核后，`Resume` 用绑定的 Profile 和项目恢复原对话。选另一个 Profile 只影响之后的创建。对话历史或连接证据失效时，界面显示具体缺项并让用户确认原环境、原对话或修复连接。 [产品契约](../spec.md)、[运行状态契约](../runtime-state.md)
3. 用户可以分别打开「工作」Profile 的 Claude Code 和「个人」Profile 的 Claude Code。两个 Profile 各自完成登录及读取自己的历史。同一个项目目录仍会共享代码文件。远程工作区中的 Profile 与对话保存在远程机器；断开前端连接时，远程工作可以继续。重新创建且缺少原历史的远程环境需要人工处理。 [Profile 契约](../profile-contract.md)、[远程工作区](../remote-workspaces.md)、[Claude 凭据存储](https://code.claude.com/docs/en/authentication)
4. Magpie 适配通过后，可在新建会话时明确选它的实例和支持的 Claude 模型，恢复仍使用这次选择；同一 Profile 可同时另开一个原生连接。会话详情应区分 API 连接与原生订阅登录，使用量归实际网关凭据。 [产品连接意图](../spec.md)、[网关计费](https://code.claude.com/docs/en/llm-gateway#subscriptions-and-gateways)

## 实施顺序与验收

1. **先交付原生闭环。** 扩展 `second_client_real.py` 覆盖仅安装 Claude、无预装 hook、真实信任界面、两个 Profile、正常退出和重启恢复。验证同一 UUID 和第二轮上下文。负例覆盖历史或配置目录丢失、换目录、身份冲突、hook 被关闭、旧记录显式关联，以及外部活动和停止过程中可能出现的未知状态。之后在 Linux amd64 和 macOS arm64 复跑，远程端单独验证断线与服务端重启。若要公布订阅支持，补真实账户的官方登录、隔离和恢复验收。 [现有第二客户端测试](../../bridge/tests/second_client_real.py)、[验收约定](../../bridge/tests/README.md)、[远程边界](../remote-workspaces.md)
2. **再验证 API 型 Magpie 的上游 launcher。** 用真实候选 Magpie 跑三个并行会话（原生、Magpie A、Magpie B），检查第一轮、工具回路和恢复后的请求都进入预期上游。用合成凭据验证配置未串线、SSE、进程生命周期和模型选择，再用授权的真实提供商补账单、凭据和能力验证。支持路由组之前，还需验证跨上游兼容与不完整流之后的行为。 [Harbor Magpie 边界](../../bridge/MAGPIE-BOUNDARY.md)、[Harbor 验收约定](../../bridge/tests/README.md)、[Anthropic 网关兼容规范](https://code.claude.com/docs/en/llm-gateway-protocol)

本次检查了当前仓库代码、锁定版本的 Herdr 和 Magpie 源码、Anthropic 官方文档和既有验收记录。阶段建议和界面流程是设计推论。本次未运行 Claude Code、Herdr 或 Magpie，也未访问用户账号或对话；当前 Profile 版本的真实运行、Claude Magpie 链路和 Herdr 查询补丁的上游接纳均需单独验证。 [Herdr 查询状态](../herdr-integration.md)
