# CLI conversation migration

Research snapshot, 2026-11-19. This note evaluates upstream interfaces against Agent Harbor `main` at `ad00eea`.

## Where to start

The first useful Harbor workflow is moving one stopped Codex Conversation to a selected Profile or host, then proving the target can resume the same thread ID. Evaluate `cct` as an optional, pinned transport helper and use Codex to verify the result. OpenAI already offers a first-party cross-host move in the ChatGPT desktop app. It is a user workflow and implementation reference, with no documented `thread/handoff` equivalent in the public App Server API reviewed here. [Codex desktop Handoff](https://learn.chatgpt.com/docs/remote-connections#hand-off-a-chat-between-hosts), [Codex App Server API overview](https://learn.chatgpt.com/docs/app-server#api-overview), [cct command reference](https://github.com/ahmojo/codex-claude-transfer/blob/Main/docs/reference.md).

Claude Code → Codex has an official programmatic import path today. It creates a new Codex Conversation carrying imported history. A local Codex 0.169.0 run below verified exact-ID resume with a synthetic Claude Code transcript. Keep this action distinct from recovering a Harbor Session or moving the same Codex thread between Profiles. [Codex external-agent import](https://learn.chatgpt.com/docs/app-server#detect-and-import-external-agent-config), [OpenAI's single-session Claude Code transfer](https://github.com/openai/codex-plugin-cc#codextransfer), [Harbor product outline](../spec.md).

## What Harbor already has

The `session` record carries client, project directory, Profile binding, exact Conversation reference and connection intent. Launch validates the original directory, bound environment, matching reference and duplicate writers. Recovery asks Herdr for a resume command via the local query patch, then launches that command. The query produces command syntax for an identity already known to Harbor. Reassociation allows a reviewed reference where the record lacks one and rejects a conflicting saved reference. [Session store](../../bridge/store.go), [launch checks](../../bridge/session_checks.go), [Herdr recovery query](../../bridge/query_recovery.go), [reassociation](../../bridge/reassociation.go), [Herdr integration and patch status](../herdr-integration.md).

A Profile binding is scoped to a workspace and owning server. Its environment ID, verified root identities and distinct Codex home, SQLite and runtime roots matter to both export and import. Harbor's documented remote flow puts execution on the selected server and reconnects to existing processes. Loading the source `sessions.json` on another server would carry the original binding, so a transfer needs a verified destination binding and its own destination-side record. New isolated Profiles currently support Codex. Other native clients use explicitly identified existing environments. [Profile service contract](../profile-contract.md), [remote workspaces](../remote-workspaces.md).

Herdr calls its server replacement during upgrade “Live handoff”. It preserves pane processes on the existing host. Agent Client Protocol v2 `session/resume` similarly reopens a session that the agent retains, with optional replay. Neither supplies a file transfer or a cross-client conversation importer for Harbor. [Herdr session state](https://herdr.dev/tui/docs/session-state/#live-handoff), [ACP v2 session setup](https://github.com/agentclientprotocol/agent-client-protocol/blob/main/docs/protocol/v2/session-setup.mdx).

Changing the account inside one Profile already uses a separate account-selection flow. A move across Profiles changes the client data root and may use a different login. A move across hosts can also change project path, provider access or Magpie instance. Harbor should show the target Profile, client, directory and connection before writing anything. A destination host resolves its own connection, including its own Magpie instance or native credentials. [Product outline](../spec.md), [Profile service contract](../profile-contract.md), [remote workspaces](../remote-workspaces.md).

## Tool choices

### Codex to Codex

- **ChatGPT desktop Handoff** is the official manual route. On macOS and Windows, Codex CLI's `/app` opens the current saved chat in the desktop app. The desktop app offers Handoff when the destination is connected and the same repository and subdirectory are saved there. Desktop visibility for a Harbor-isolated Profile is unverified. [Codex `/app`](https://learn.chatgpt.com/docs/developer-commands?surface=cli#continue-in-the-desktop-app-with-app), [Codex Handoff](https://learn.chatgpt.com/docs/remote-connections#hand-off-a-chat-between-hosts).
- **`cct`** is the best third-party helper to evaluate first. It is a released MIT-licensed Go CLI with a single-session selector, configurable Codex and Claude homes, an inspect and dry-run workflow, checksummed bundles, JSON output, explicit `cwd` mapping and a no-overwrite default. Its opt-in `--reconcile` asks Codex App Server to read missing IDs and verifies discovery using `thread/list`. The tool writes native rollout files and delegates index registration to Codex. Its upstream native canary covers Codex **0.161.0** and Claude Code **2.1.292** on Windows with disposable homes and mock APIs. Harbor currently uses **0.169.0** for its Profile evidence, which needs a fresh compatibility check. Native Codex fork history may require parent rollouts, and compressed rollouts need `zstd` for transformations. The upstream docs describe additional Claude persisted state including tasks and opt-in memory. [cct v2.1.6](https://github.com/ahmojo/codex-claude-transfer/releases/tag/v2.1.6), [command reference](https://github.com/ahmojo/codex-claude-transfer/blob/Main/docs/reference.md), [compatibility table](https://github.com/ahmojo/codex-claude-transfer#compatibility), [canary](https://github.com/ahmojo/codex-claude-transfer/blob/Main/docs/research/agent-canary-2026-10-07.md).
- **Codex Migrate** is a recovery and bulk migration option. It supports mapping project paths, selecting sessions, refusing divergent histories with the same UUID, staging writes and restoring rollback snapshots. It works directly with Codex's SQLite/index structures, recommends shutting Codex down, and its full-home backup includes private logs, config and caches even though it excludes root-level login credential files. That larger scope and direct database coupling make `cct` the better fit for a narrowly scoped Harbor move. [Codex Migrate v1.0.8](https://github.com/ChenglongLi777/codex-migrate/releases/tag/v1.0.8), [backup and merge behavior](https://github.com/ChenglongLi777/codex-migrate#backup-contents).
- **ai-profiles** is an implementation reference for same-machine, same-client Profile moves. Its macOS app copies a Codex rollout, registers it using App Server and archives the source with a Restore action. Its own app and profile layout differ from Harbor's server-owned model. [ai-profiles session moves](https://github.com/bartekczyz/ai-profiles#sessions).

### Transfers between clients

- **Codex external-agent import** exposes `externalAgentConfig/detect` and `externalAgentConfig/import`. Submit only an explicit `SESSIONS` item, track the returned `importId`, and check the per-item completion result. OpenAI's `/codex:transfer --source <file>` shows the single-transcript request and returns `codex resume <id>`. The plugin constrains its source to `~/.claude/projects` and resolves the ID using a Codex import ledger keyed by canonical path and content hash. Verify how the tested Codex build returns or records the destination ID before binding it in Harbor, especially with alternate `CLAUDE_CONFIG_DIR` and retry. The interactive `/import` is a separate recent-history picker limited to 50 chats from the last 30 days and operates on the machine running Codex or its connected server. [App Server import and completion](https://learn.chatgpt.com/docs/app-server#detect-and-import-external-agent-config), [OpenAI plugin usage](https://github.com/openai/codex-plugin-cc#codextransfer), [plugin source](https://github.com/openai/codex-plugin-cc/blob/main/plugins/codex/scripts/lib/codex.mjs), [CLI import](https://learn.chatgpt.com/docs/import?surface=cli#import-in-codex-cli).
- **`session-migrate` (`smigrate`)** is a candidate for unsupported pairs. The MIT Python CLI has explicit source, target, session ID and directory selectors, supporting Codex, Claude Code, OpenCode, Pi and others. Its published matrix uses one native-produced fixture per harness. It gives the target a new identity and may lose tool/media entries, summaries or subagent information. Private/signed reasoning and auth, MCP, policies and runtime config stay outside the transfer. [session-migrate v0.13.0](https://github.com/xhluca/session-migrate/releases/tag/v0.13.0), [transfer fidelity](https://github.com/xhluca/session-migrate#what-survives).
- **`txcript`** is an Apache-2.0 Rust library and CLI with read and write support for Codex, Claude Code, OpenCode, Pi and others. Its common format, explicit adapter API and published storage notes make it a candidate if Harbor needs an isolated converter with a smaller interface. Preservation depends on both formats. The destination supplies its own instructions and tools, and needs its own project files. [txcript v0.14.4](https://github.com/skillsynchq/txcript/releases/tag/v0.14.4), [supported agents and fidelity](https://github.com/skillsynchq/txcript#supported-agents).
- **`casr`** includes Gemini CLI as a source and destination and exposes a broad compatibility matrix. Its documentation lists OpenCode 1.x and 2.x as read-only for their current SQLite layouts and declares a license rider. Evaluate the exact target pair and license terms before relying on it. [casr compatibility and license](https://github.com/Dicklesworthstone/cross_agent_session_resumer).

## Local Codex probes

On 2026-11-19, both probes ran native Codex CLI **0.169.0** on macOS arm64 with isolated `HOME`, `CODEX_HOME` and `CODEX_SQLITE_HOME` directories. The current upstream release was **0.170.0**. [Codex 0.169.0 release](https://github.com/openai/codex/releases/tag/rust-v0.169.0), [Codex 0.170.0 release](https://github.com/openai/codex/releases/tag/rust-v0.170.0).

- **Codex → Codex.** The source created one completed turn with a loopback synthetic Responses backend. Resuming its exact ID in an empty target failed as expected. Copying only its raw legacy rollout JSONL allowed `codex exec resume <id>` to reopen the same UUID and send both the original and continuation prompts to the mock backend. The first destination used the original project folder. The second selected a different folder with `-C`, and its stored rollout retained the old path alongside new metadata. The source rollout stayed byte-identical.
- **Claude Code → Codex.** A synthetic JSONL transcript with one user/assistant exchange was placed under the isolated `~/.claude/projects`. The native Codex App Server over stdio detected it, imported the single selected `SESSIONS` item, and reported one successful import with the matching `importId`. `thread/list` found a new Codex ID distinct from the Claude UUID. The target accepted exact-ID `thread/resume` and exposed both messages in its history. The source SHA-256 stayed the same. This probe used a hand-built transcript and ended before sending another model request.

The installed build's generated experimental schema included `externalAgentConfig/import` and the `thread/resume` fields `path`, `history`, `cwd` and `threadId`. It exposed no `thread/handoff`, `thread/transfer`, `thread/export` or `thread/import` method. The upstream source marks `path` and `history` experimental and gives them precedence over the ID for a non-running thread. If testing those fields, compare the returned ID independently. [Codex App Server API](https://learn.chatgpt.com/docs/app-server#api-overview), [upstream `ThreadResumeParams`](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/src/protocol/v2/thread.rs#L2820-L2877).

`cct`, moving a thread in Codex's paginated storage mode between homes, Codex desktop Handoff, a real Claude Code process, real accounts, SSH and the interactive Herdr flow remain untested in this investigation. Third-party canary results above come from the tools' maintainers.

## Proposed Harbor prototype

1. Start with two isolated Codex Profiles and a stopped root Conversation that contains at least two completed turns. Resolve source and target through Harbor's existing Profile service, including the actual `CODEX_HOME` and SQLite location. Bind both operations to the verified source/target and reject an active or ambiguous writer. Start on one machine so the first test isolates the persistence problem.
2. Export exactly the selected thread and stage it privately. Dry-run the import against the explicit destination, verify the target project and `cwd` mapping, then import without overwrite. Send only the selected Conversation's required data. Keep credentials, full-home configuration, approval state and project contents outside the transfer workflow. Confirm target repository and branch independently.
3. Read the target with a target-scoped Codex App Server, then resume the exact ID through the normal client entry point and append a turn. Verify the thread ID, prior turns, target `cwd` and connection, visibility after restart, and source state. A `thread/read` or populated picker alone is insufficient to prove the target can continue. Codex publicly documents `thread/read`, `thread/resume`, `thread/list` and paginated history endpoints. [Codex App Server API](https://learn.chatgpt.com/docs/app-server#api-overview).
4. Have Harbor create the destination record only after verification. For a move, mark the source as transferred after destination verification, export a recovery path and keep its history recoverable. On interruption, leave a recoverable source and retry idempotently using the same source/destination pair and artifact checksum. A divergent UUID conflict requires review.
5. Extend the same experiment to owned local → remote and remote → local workspaces, keeping writes on the owning host. Exercise differing project paths, mismatched or changed target Profiles, retry after partial failure, expired or unavailable target connection, and no existing destination history. Test richer cases separately, including fork parents, compacted history, side threads, images, long paths, and different Codex versions. Mac/Linux and an isolated real-client run are the minimum for a Harbor release claim. [Harbor isolated acceptance guide](../../bridge/tests/README.md).

This investigation did not change product behavior or packaging.
