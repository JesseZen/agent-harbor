# 人工代码审阅入口：Herdr、Codex 与 Claude Code

研究快照：2026-11-19。依据官方文档、发行记录和可查的上游源码，区分已提供的用户入口、开发接口和 Harbor 的待验证方案。版本以 [Codex CLI/App Server 0.170.0](https://github.com/openai/codex/releases/tag/rust-v0.170.0)（`29eb79e9866b3262a777fdf8195c1b9e63684c91`）、[Claude Code CLI 2.1.328](https://github.com/anthropics/claude-code/releases/tag/v2.1.328)（`26fdd0013f7800348867d6c9c25143fcfd089ec6`）、[Agent SDK TypeScript 0.3.328](https://github.com/anthropics/claude-agent-sdk-typescript/releases/tag/v0.3.328) 和 [Python 0.2.185](https://github.com/anthropics/claude-agent-sdk-python/releases/tag/v0.2.185) 为基线。桌面和移动端按各自官方文档描述，不能用 CLI 版本代替 App 版本。

## 先看结论

- **Herdr TUI 首选 `herdr-reviewr`**：它已有逐文件 diff、并排视图和行评。macOS 隔离实测通过：独立模式能在 Herdr popup 打开指定 worktree，不连接 Herdr socket，不碰对话或账户。建议 Harbor 先复用查看器，不从头实现；远端和 Linux 仍待验证。见 [Reviewr v0.52.2](https://github.com/persiyanov/herdr-reviewr/releases/tag/v0.52.2) 和[实测记录](#验证范围)。
- **不装工具也能在原终端看**：回到原客户端输入 `/diff`。Codex 看 Git 变更（所查版本不含仅暂存的 tracked diff）；Claude Code 还能切到单轮的文件编辑。`/review` 是让模型审查代码，不是 diff 查看器。见 [Codex CLI 命令](https://learn.chatgpt.com/docs/developer-commands?surface=cli#review-changes-with-diff)、[Claude CLI diff](https://code.claude.com/docs/en/interactive-mode#review-changes-with-/diff) 和 [Claude Code Review](https://code.claude.com/docs/en/code-review-local)。
- **本机想在官方 App 里审同一条已保存对话**：Codex 用 `/app`，按 ID 打开且不退出 CLI；Claude 用 `/desktop`，交接后退出 CLI，也可以用 `claude --desktop --resume <session-id>` 打开已停止的对话。两者都不等于从笔记本接管 Linux 上的 Harbor CLI，隔离 Profile 的可见性也要另验。[Codex `/app`](https://learn.chatgpt.com/docs/developer-commands?surface=cli#continue-in-the-desktop-app-with-app)、[Claude Desktop 交接](https://code.claude.com/docs/en/desktop#coming-from-the-cli)
- **最接近「远程看原来正在跑的 CLI」的是 Claude Code Remote Control**：合格的 Claude 订阅直连可以在原 CLI 上启用，从 Web 或 Claude App 看同一运行中的对话和 Git diff，不需要退出终端；API key、自定义 Anthropic 网关与部分企业策略不符合条件。[Remote Control 启用及要求](https://code.claude.com/docs/en/remote-control#requirements)

## Codex

| 入口 | 人能看什么、能做什么 | 与原 CLI 的关系 |
| --- | --- | --- |

| ChatGPT 桌面 App，Codex review pane | `Unstaged`（默认）、`Staged`、`Commit`、`Branch` 是 Git 视图，可混入人或其它进程的变更；`Last turn` 才是最近一轮助手的视图，也能汇总多个已连接仓库。支持行级反馈后发回聊天，及整份、文件或 hunk 级的暂存、取消暂存或撤销；这些是不同操作。[桌面代码审阅](https://learn.chatgpt.com/docs/code-review?surface=app) | macOS / Windows 的 CLI `/app` 打开当前**已保存**对话。`0.170.0` 把准确 ID 交给 `codex://threads/<threadId>`，不会迁移 checkout、附带 Profile 或服务器地址，也不退出 CLI。`codex app [PATH]` 是项目启动入口，不是按对话 ID 打开。不能把 URL 实现当成面向第三方的稳定、跨主机寻址接口；不要在两端同时发起写入。[`/app`](https://learn.chatgpt.com/docs/developer-commands?surface=cli#continue-in-the-desktop-app-with-app)、[`codex app`](https://learn.chatgpt.com/docs/developer-commands?surface=cli#codex-app)、[0.170.0 URL 实现](https://github.com/openai/codex/blob/29eb79e9866b3262a777fdf8195c1b9e63684c91/codex-rs/tui/src/app/history_ui.rs#L304-L316) |
| ChatGPT 桌面 App 的 SSH / 移动端 Remote | 桌面可通过 SSH 打开远端项目，命令和代码文件留在远端。手机可经已配对的桌面宿主查看远程任务；OpenAI 展示了文件级 diff、源码和行评发回原聊天。[SSH 与配对](https://learn.chatgpt.com/docs/remote-connections#connect-to-an-ssh-host)、[移动端审阅示例](https://learn.chatgpt.com/blog/mastering-codex-remote-for-engineering) | SSH 入口用**远端登录 shell** 的 `PATH` 启动远端 App Server；能看同一 checkout 不等于会接入 Harbor 已运行的 CLI 或读到隔离 Profile。App 内的 Handoff 是显式把已打开的聊天及 Git 状态移到匹配项目/worktree，进行中的回复会中断，不是只读旁观。[远程 Handoff](https://learn.chatgpt.com/docs/remote-connections#hand-off-a-chat-between-hosts)、[Harbor Profile 环境策略](../profile-contract.md#environment-policy-and-account-integration) |

`/review`、`codex review` 和 `review/start` 都是 **AI 审查**，可选未提交变更、基线分支、单个提交或自定义范围（具体选项依入口）。App 中模型发现也能显示为行评，但不是人工评论。人工行评是给下轮的反馈，`item/fileChange/requestApproval` 与 `item/commandExecution/requestApproval` 是本次动作的权限请求；其中任何一个都不等于 Git/PR 审批。[Code review](https://learn.chatgpt.com/docs/code-review)、[App Server Review](https://learn.chatgpt.com/docs/app-server#review)、[App Server Approvals](https://learn.chatgpt.com/docs/app-server#approvals)

### App Server：能用哪些数据，能接到哪里

- **按轮看编辑**：`turn/diff/updated` 提供 `threadId`、`turnId` 与聚合 unified diff；`item/*` 里的 `fileChange` 提供 `path`、`kind`、`diff` 和操作状态，可把同轮的 patch 与最终结果对应。`0.170.0` 的 turn tracker 输入是已应用的 patch delta：不要把它当成 Git 快照、所有 shell 写入的完整记录或重连后必定可回放的事件。需要完整 checkout 时另读 Git。协议里也有源码级的 v1 `gitDiffToRemote`，按 `cwd` 返回相对上游 Git 基线的 `{sha, diff}`，不是按对话查变更，也不是桌面审阅面板接口。[事件文档](https://learn.chatgpt.com/docs/app-server#turn-events)、[固定版本的协议表](https://github.com/openai/codex/blob/29eb79e9866b3262a777fdf8195c1b9e63684c91/codex-rs/app-server-protocol/src/protocol/common.rs#L2083-L2115)、[turn tracker](https://github.com/openai/codex/blob/29eb79e9866b3262a777fdf8195c1b9e63684c91/codex-rs/core/src/turn_diff_tracker.rs#L79-L108)、[v1 请求](https://github.com/openai/codex/blob/29eb79e9866b3262a777fdf8195c1b9e63684c91/codex-rs/app-server-protocol/src/protocol/common.rs#L1589-L1593)、[Git 基线实现](https://github.com/openai/codex/blob/29eb79e9866b3262a777fdf8195c1b9e63684c91/codex-rs/git-utils/src/info.rs#L357-L369)。
- **同一 ID 不等于同一进程**：`thread/list` 和 `thread/read` 可按服务实例和持久化环境查历史；`thread/resume` 在拥有该活动 thread 的**同一 App Server** 上能接到已加载的 thread，在另一个实例读取同一历史则不是订阅原来的进程。Codex CLI 可用 `--remote` 连接明确的 App Server；没有端点的内嵌 TUI 不能靠知道 ID 接入。Harbor 的隔离 Profile 默认禁用共享 daemon；只有显式打开实验性账户功能时才有当前的专用 App Server/Unix socket 拓扑，它不是现成的审阅接口。[Thread API](https://learn.chatgpt.com/docs/app-server#threads)、[运行中 resume 实现](https://github.com/openai/codex/blob/29eb79e9866b3262a777fdf8195c1b9e63684c91/codex-rs/app-server/src/request_processors/thread_processor.rs#L4667-L4723)、[CLI 连接说明](https://learn.chatgpt.com/docs/app-server#connect-the-cli-terminal-ui)、[Harbor Profile](../profile-contract.md#environment-policy-and-account-integration)、[实验启动路径](../../bridge/launch.go#L265-L280)。
- **自建界面，而非嵌入原生界面**：公开协议提供事件、对话、输入和权限请求；所查版本没有让第三方嵌入 Codex 原生 Review 面板或写入它的 Git 行评草稿的接口。`turn/start` 可送明确的用户反馈，但不是原生评论 API；[Annotations Extensibility](https://learn.chatgpt.com/docs/annotations-extensibility) 面向浏览器页面，不是 Git diff。协议随版本变化，应用前用目标二进制生成 schema。若验证远程，只用已验证服务器上的私有 socket 或受控 SSH 通道，不暴露无认证监听口。[App Server 协议与 schema](https://learn.chatgpt.com/docs/app-server#protocol)、[固定版本请求表](https://github.com/openai/codex/blob/29eb79e9866b3262a777fdf8195c1b9e63684c91/codex-rs/app-server-protocol/src/protocol/common.rs)。
- **另有实验性 CLI Remote Control**：`codex remote-control` 可走符合条件的 daemon 或独立前台 App Server，`pair` 可生成短时配对码；桌面宿主的移动配对是另一条明确记录的用户流程。不能由配对命令推断它会接管既有、独立运行的 Harbor TUI，或保持该会话的登录及 Magpie 连接。[CLI Remote Control](https://learn.chatgpt.com/docs/developer-commands?surface=cli#codex-remote-control)、[0.170.0 实现](https://github.com/openai/codex/blob/29eb79e9866b3262a777fdf8195c1b9e63684c91/codex-rs/cli/src/remote_control_cmd.rs#L58-L153)、[桌面配对](https://learn.chatgpt.com/docs/remote-connections#set-up-mobile-access)。

## Claude Code

| 入口 | 人能看什么、能做什么 | 与原 CLI 的关系 |
| --- | --- | --- |
| CLI `/diff` | 全屏有旁边实时更新的 diff panel；经典模式是弹窗。`Current` 看 Git 工作树，`T1`、`T2` 等看 Claude 通过文件编辑记录的单轮变化；shell 改文件只出现在 Git 视图，不进逐轮记录。全屏可切换本会话范围、全部未提交和相对默认分支，并用 `ask` 把单个文件 diff 附到下一条消息；这不是桌面的逐行批注。当前文档的全屏面板要求 Git 仓库、至少 110 列和 CLI `2.1.287+`。[交互式 diff](https://code.claude.com/docs/en/interactive-mode#review-changes-with-/diff) | 原 CLI 直接使用，不需要 App 或另开对话。 |
| Claude Desktop 的 Code tab → Changes | 逐文件看 diff、写多条行评后一起提交，由 Claude 根据反馈修改。`/code-review`（`/review` 是别名）则让模型检查，Desktop 本地/SSH/WSL 可把发现放到对应行；其中的 `Apply fixes` 请求模型修改，不等于人工确认代码。[Desktop diff 与 review](https://code.claude.com/docs/en/desktop#review-changes-with-diff-view)、[命令表](https://code.claude.com/docs/en/commands)、[审查参数](https://code.claude.com/docs/en/code-review-local) | 本地终端 `/desktop`（别名 `/app`）保存并打开同一对话，然后退出 CLI。CLI `2.1.285+` 可对**已停止**的会话执行 `claude --desktop --resume <session-id>`；Desktop 本地 `/resume` 也可接同一对话而不是复制。官方交接要求 macOS 或 x64 Windows、Claude 订阅；不支持 API key 或列出的第三方平台。Desktop 内的 `/resume` 不适用于 SSH、WSL 或云会话。不要用 `--continue` 猜 Harbor 要打开哪一条。[Desktop/CLI 交接规则](https://code.claude.com/docs/en/desktop#coming-from-the-cli)、[2.1.285 发行记录](https://github.com/anthropics/claude-code/blob/26fdd0013f7800348867d6c9c25143fcfd089ec6/CHANGELOG.md#L3507) |
| Claude Desktop SSH | 在远端选目录，使用 Desktop 的审阅面板；Desktop 安装并启动远端 Claude Code，文件在远端。[SSH sessions](https://code.claude.com/docs/en/desktop#ssh-sessions)、[Changes 面板](https://code.claude.com/docs/en/desktop#review-changes-with-diff-view) | 不要把 Desktop 管理的 SSH 会话重连，当成接管任意 Herdr pane 里的 CLI。能打开同目录，不等于同运行进程。 |
| Claude Code Remote Control → Web / Claude App | 在已有 CLI 使用 `/remote-control`（`/rc`），或启动时用 `claude --remote-control`。从官方链接、QR 或会话列表进入，终端照常可用。连接端在 Git 仓库里有 diff pane：分支领先默认分支时看分叉以来的变更（含未提交变更），否则只看未提交变更；这是 checkout/分支范围，不是 `T1` 视图。所查 Remote Control 文档没有确认和 Desktop 原生行评同等的操作。[连接方式和显示范围](https://code.claude.com/docs/en/remote-control#what-connected-devices-see) | **复用原 CLI**，执行与文件系统仍在启动进程的机器上，也就是 Harbor 远程工作区的服务器；不是 Claude 云任务。要求合格订阅、官方直连及适用的管理员策略；自定义 `ANTHROPIC_BASE_URL` 指向网关/代理时不适用。启用后 Anthropic 保存用于同步的对话和工具活动，应让用户显式选择，不默认打开。[要求](https://code.claude.com/docs/en/remote-control#requirements)、[连接与安全](https://code.claude.com/docs/en/remote-control#connection-and-security) |

Remote Control 的 URL ID 不应代替 Harbor 保存的 CLI 对话引用：官方的 `claude remote-control --session-id` 针对先前由 Remote Control **server mode** 服务的 URL ID；交互终端的历史用 `claude --resume` 恢复。特别是终端 `/resume` 切换后，连接可能断开，或新消息同步到当前对话但不更新旧标题及较早历史，不能用窗口标题或旧 URL 核验反馈目标。[切换对话](https://code.claude.com/docs/en/remote-control#what-connected-devices-see)、[恢复 server mode](https://code.claude.com/docs/en/remote-control#resume-sessions-after-stopping-the-server)

### Agent SDK：会话与工具数据，不是 Desktop 插件

- TypeScript `listSessions()` / `getSessionMessages()`（Python 对应 `list_sessions()` / `get_session_messages()`）用于读可找到的本机 transcript；按 ID `resume` 继续已保存历史，`fork` 建新 ID。读历史无需启动已有 agent，但不是能订阅任意运行中的 CLI。SDK 的流式回调属于 SDK 自己开的运行；与 CLI 共用引擎或文件配置不等于共享进程或可嵌入 Desktop 的 Changes 面板。[TS 参考](https://code.claude.com/docs/en/agent-sdk/typescript#getsessionmessages)、[Python session browser](https://platform.claude.com/cookbook/claude-agent-sdk-05-building-a-session-browser)、[resume/fork](https://code.claude.com/docs/en/agent-sdk/sessions)、[SDK 与 CLI 的共用边界](https://code.claude.com/docs/en/agent-sdk/claude-code-features)。
- `canUseTool`、`PreToolUse` 是动作权限/拦截；`PostToolUse` 可以采集工具结果，不是已完成代码的人工 review。应用可用工具输入输出自行做预览，或用 TypeScript checkpoint 的 `rewindFiles(..., { dryRun: true })` 查看可回退文件及行数；checkpoint 不是完整 Git diff，任意 Bash 写入和子代理编辑覆盖有明确限制。因此不能用来保证展示所有 agent 更改，更不是 Claude Desktop 行评 API。[用户输入与审批](https://code.claude.com/docs/en/agent-sdk/user-input)、[SDK hooks](https://code.claude.com/docs/en/agent-sdk/hooks)、[RewindFilesResult](https://code.claude.com/docs/en/agent-sdk/typescript#rewindfilesresult)、[checkpoint 的限制](https://code.claude.com/docs/en/agent-sdk/file-checkpointing#limitations)。

## Herdr 与 Harbor

Harbor 构建使用 [Herdr TUI `ee5bfb5`](https://github.com/herdrdev/herdr/tree/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde) 加本地补丁；对照稳定版 [v0.9.5](https://github.com/herdrdev/herdr/releases/tag/v0.9.5)。所查 TUI 没有内建代码审阅面板，但官方支持用 `[[keys.command]]` 在项目所在机器打开 popup，示例用 `lazygit`；Harbor 可以复用这个机制跑专用的 diff 查看器。[Harbor 构建脚本](../../distribution/build-dependencies.sh#L8-L17)、[补丁状态](../herdr-integration.md)、[上游 popup 配置](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/docs/next/website/src/content/docs/configuration.mdx#L185-L228)、[Harbor 远程执行边界](../remote-workspaces.md#implementation-and-validation)。

> 旁注：另一个产品 Herdr Desktop（[发行清单](https://releases.herdr.dev/app/latest.json) `0.1.16`）有 [Changes 面板](https://github.com/herdrdev/herdr-app/blob/317e673f1f1568b876cbaa0b41dabeb9153ecbea/defaults/mods/changes/main.js#L81-L154)，但用独立的 `herdr-core`，可以看同一 checkout，不能接入 Herdr TUI/Harbor 的 agent（[官网 FAQ](https://herdr.dev/)）。

### 首选：Herdr Reviewr

- **独立模式**：MIT、[v0.52.2](https://github.com/persiyanov/herdr-reviewr/releases/tag/v0.52.2)（`bb71050caa5d3a0b1a414527783eb7a772447f9f`）。在项目所属机器运行 `herdr-reviewr /path/to/worktree`，能看高亮文件列表、统一/并排 diff、未提交/分支/提交范围，能写行或行范围批注，`y` 可复制。未连接 Herdr 时不提供 `Send` 和 `Last turn`，打开、查看不需要 LLM 账户。批注留在内存，未导出就关闭会丢失；远端 `y` 依赖远端剪贴板工具，不承诺复制到本地笔记本。二进制、大于 2 MB 或超过 50,000 行的文件不显示文本 diff。[独立用法](https://github.com/persiyanov/herdr-reviewr/blob/v0.52.2/README.md#install)、[限制](https://github.com/persiyanov/herdr-reviewr/blob/v0.52.2/README.md#limitations)、[复制实现](https://github.com/persiyanov/herdr-reviewr/blob/v0.52.2/src/export.rs#L70-L109)。
- **仓库副作用**：不修改工作树、真实 index 或分支，但普通 diff 也会在 Git 元数据目录创建私有 index 副本；更改选中的基线可写 `refs/worktree/reviewr/` 和对象，插件的 turn 快照也会写 Git 对象。`e` 会打开外部编辑器，PR 页可调用已登录的 forge CLI。第一轮只比较可信 checkout 的本地 Git 变化，不启用 PR/外部编辑器；如果产品承诺连 `.git` 都不写，不能直接拿这个二进制当严格只读实现。[仓库写入契约](https://github.com/persiyanov/herdr-reviewr/blob/v0.52.2/AGENTS.md#invariants)、[私有 index](https://github.com/persiyanov/herdr-reviewr/blob/v0.52.2/src/git.rs#L1836-L1878)、[基线写入](https://github.com/persiyanov/herdr-reviewr/blob/v0.52.2/src/git.rs#L1658-L1667)、[编辑器及 PR 功能](https://github.com/persiyanov/herdr-reviewr/blob/v0.52.2/README.md)。
- **插件模式另验**：要求 Herdr `0.9.3+`。`s` 选相邻/可用的 agent，`S` 让用户选；源码通过 `pane.send_text` **只粘贴未提交草稿，不按 Enter**。目标选择和粘贴不是一个原子操作，pane 也不是 Harbor 已验证的 Conversation，不能直接用于保证定向反馈。`Last turn` 是观察 Herdr 活动变化后打 worktree 快照，早期写入可能与快照竞争，共享 worktree 上的其它写入也可能混入；不是 Codex/Claude 的 turn 事件或归属证明。[插件 manifest](https://github.com/persiyanov/herdr-reviewr/blob/v0.52.2/herdr-plugin.toml)、[发送实现](https://github.com/persiyanov/herdr-reviewr/blob/v0.52.2/src/herdr.rs#L661-L700)、[turn 观察实现](https://github.com/persiyanov/herdr-reviewr/blob/v0.52.2/src/turn.rs#L426-L445)。

**备选**：[tuicr v0.29.0](https://github.com/agavra/tuicr/blob/a8185f2c701ed213c8407b8bda79dd6487d302ec/README.md) 不依赖 Herdr，进已验证的 checkout 用 `tuicr -w` 或 `tuicr -r <base>..HEAD`，支持行评、复制 Markdown 或 `--stdout`，不需要接入 agent；首轮不走 PR 的 `:submit`。`lazygit` 能看 Git diff，下面有 popup 实测，但也能改 Git，不作为默认只读审阅器。[alexeyco/herdr-review](https://github.com/alexeyco/herdr-review/blob/v0.3.2/README.md#the-flow) 会在审阅工具退出后向 agent 交付批注，不适合作默认入口。

其它参考：[herdr-diffview](https://github.com/RuslanGrigoryev/herdr-diffview/blob/0a7d29a556bcca7089c51b70b468fedb9db5a6e4/README.md) 可用 `--path` 看 worktree；[herdr-diff-viewer](https://github.com/odiumuniverse/herdr-diff-viewer/blob/474e85aed32e0c1fe914d8556b8f0e5e53293da3/README.md) 用 journal 和进程信号推断要看的仓库，不证明代码归属；[herdr-diff-review.nvim](https://github.com/rytkmt/herdr-diff-review.nvim/blob/5eb0da10f0287f75b5bf5fbe57a4b741fbd46da4/README.md) 是 Claude 工具执行前的批准/拒绝，不是完整的事后审阅。

### Harbor 的最小方案

1. **先在 popup 复用 Reviewr**：从选中的 Harbor 会话取已验证的所属服务器和项目目录，在该服务器解析实际 Git 根目录和 worktree，显示机器、路径、分支及基线。启动独立二进制并清掉 `HERDR_SOCKET_PATH`、`HERDR_WORKSPACE_ID`、`HERDR_PANE_ID`，不要装插件或赋予同步/写终端能力。当前记录有 `WorkingDirectory`，Harbor 已生成自己的 Herdr popup 快捷键；仍需核对实际 checkout（例如客户端切过目录或进入另一 worktree）。目标不明确时要求选择，不回退到本机、焦点窗格或同名仓库。[会话记录](../../bridge/store.go#L75)、[快捷键生成](../../bridge/herdr.go#L245)、[popup 配置](../../bridge/popup_upgrade.go#L59)、[远程边界](../remote-workspaces.md)、[Reviewr 如何发现 Herdr socket](https://github.com/persiyanov/herdr-reviewr/blob/v0.52.2/src/lib.rs#L916-L929)。
2. **把 checkout 和归属分开标**：首轮解释 Reviewr 的未提交视图是相对 `HEAD` 的合并视图，不是独立的 staged/unstaged 对比。若做完整入口，区分暂存、未暂存、未跟踪和已提交范围；选定基线解析为 SHA，不和未提交状态混算。共享 checkout 会包含不同来源；给会话独立 worktree 比从 diff 猜作者可靠。Git 查看应禁止外部 diff、textconv 和可执行 filter，限制输出，不刷新真实 index，不自动上传代码或对话；不能把这组要求当成已验收的第三方行为。[Git diff](https://git-scm.com/docs/git-diff)、[Git worktree](https://git-scm.com/docs/git-worktree)、[Reviewr Git 实现](https://github.com/persiyanov/herdr-reviewr/blob/v0.52.2/src/git.rs#L2070-L2094)、[Codex 的 filter 防护参考](https://github.com/openai/codex/blob/29eb79e9866b3262a777fdf8195c1b9e63684c91/codex-rs/tui/src/get_git_diff.rs#L163-L207)。
3. **反馈另做、显式发送**：若后续要回到原对话，让用户先核对所属机器、Profile、客户端、连接意图、准确对话 ID 和 diff 版本，再明确发送带文件/行号的反馈。不要把查看、发表评论、批准工具、暂存或提交合并成一步。不改账户或路由，不启动第二个写入进程。原生 GUI 跳转先单独验证；见 [Harbor 恢复约束](../spec.md)、[对话迁移研究](cli-conversation-migration.md) 与 [Magpie caller-only 边界](../magpie-caller-integration.md)。

**不能从 Sessions 弹窗直接再叠一个 Herdr popup。** Herdr 的 popup 是单实例；已有一个时，`plugin.pane.open` 请求另开 popup 会返回 `ui_busy`，而且 popup 不能用 `target_pane_id` 指向后台会话。独立快捷键的实测只验证了查看器；若从 Sessions 选中行进入，需要另验复用当前 PTY 或退出菜单后交接到查看器的路径。[Herdr popup 文档](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/docs/next/website/src/content/docs/plugins.mdx#L299-L338)、[服务端限制](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/app/api/plugins/mod.rs#L491-L525)。

## 验证范围

**首选实测：Herdr popup + Reviewr，macOS arm64。** 并行调查校验了 [Reviewr v0.52.2 官方 macOS arm64 tar](https://github.com/persiyanov/herdr-reviewr/releases/tag/v0.52.2) 的 SHA-256（`8d759abeb0757fa472e34f915445c1f239569890673772eb8650a7a963a6373c`），版本以发布资产为准，不用会打开 TUI 的 `--version`。在隔离 `190×47` tmux 用 Herdr `0.9.5` 的 `prefix+alt+g` 打开 90% 宽高 popup，运行 `env -u HERDR_SOCKET_PATH -u HERDR_WORKSPACE_ID -u HERDR_PANE_ID herdr-reviewr --base main <fixture-feature-worktree>`（最后一个参数替换为夹具的绝对路径）。

- `[uncommitted]` 列出暂存、未暂存和未跟踪文件，显示暂存文件准确的增删行；不显示另一 `main` worktree 的改动，也不包含 `feature` 已提交的文件。
- 按 `b` 切到 `[branch] vs main`，包含该提交在内共四个文件。按 `q` 回到原 pane `w1:p1`；真实 index 的 SHA-256、`HEAD` 和 porcelain 前后相同。这不排除工具自己的 Git 元数据写入。
- 没有安装完整插件、启动活动 agent、测试草稿交付或 `Last turn`；没有改 Harbor 菜单、登录账户或改动用户服务。Linux、远程和原生 App 均未运行验收。

**备选实测：Herdr popup + Lazygit，macOS arm64。** 同系列夹具使用 Harbor 随包的 Herdr `0.9.5`、Homebrew [Lazygit `0.66.2`](https://github.com/jesseduffield/lazygit/releases/tag/v0.66.2) 和 Apple Git `2.54.0`，在私有 `HOME`、XDG、socket 及 `150×43` tmux 中跑相同快捷键及尺寸的 popup。关闭 Lazygit 启动弹窗、自动 fetch、自动刷新及外部变更探测，设置 `GIT_OPTIONAL_LOCKS=0`。能看到暂存、未暂存（含 patch）和未跟踪文件，不会串到主 checkout 的 `main_only.txt`；按 `q` 回到原 pane，index SHA-256、`HEAD` 和 porcelain 不变。只验证查看流程，写操作仍可用。

**还要验证。** Harbor 入口需要在本地和远端各用临时 worktree 验收：同名但不同服务器或 worktree 不串；真实 index、文件、客户端进程和对话都不变；窄屏和重连仍指向原对象。Codex `/app` 能否发现隔离 Profile、桌面 SSH 能否看到 Harbor 的准确 thread 和连接、Claude Desktop 交接是否能读到定制环境、Remote Control 的行评体验，都是独立的后续验证。[Harbor 隔离验收说明](../../bridge/tests/README.md)。
