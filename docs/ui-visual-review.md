## 统一后的摆放规则

1. **标题/导航固定顶部。** 顶层页面共享同一标题高度、导航样式与间距；子任务不重复整套顶层导航。导航窄屏先缩短文字，必要时显示当前项及可切换提示，避免五个标签挤成不可预测的两三行。原 emoji 保留；示意稿的文字标签只是布局简写。
2. **正文只放任务内容。** 普通字段采用同一 label/value 列；同一角色使用同一颜色。说明为灰色，分区为淡紫，状态用明确文字；不把注意事项、路径、当前状态全部渲染成一样的白色正文。
3. **状态、动作、键位有固定顺序。** 正文下方预留消息行；再一排动作；最后一行键位。无消息时空着，不用重复说明填满。所有页面最后一行确实是最后一行，不能再靠 padding 留出几行死区。
4. **主动作与上下文一致。** 只有一个青绿主按钮；当前没有可选账号时主操作是 Add login，而不是 Select saved login。危险操作保留明确动词和安全默认焦点，不仅靠颜色区别。宽度不足先折叠长尾动作，再堆叠必要按钮。
5. **键位栏不是第二套按钮区。** 显示当前焦点最需要的动作，不复述整页所有按钮；统一为 `Tab focus  Enter ...  Esc ...  ? help` 的键/说明层级。输入时改为编辑提示，实际不能滚动时不出现 `↑↓ scroll`。更多键位进 Help，不能为了压缩把真实能力变成隐藏操作。
6. **一类任务一个页面壳。** Profile 新建/重命名、会话新建名称/重命名共享编辑壳；Session/Magpie 确认共享确认壳；目录、客户端、实例、模型共用 picker 的搜索/列表/说明/操作结构。内容可以不同，按钮和提示不应随之换位置。

## 可数的杂乱

- 当前实际边框深度为 Herdr popup + Harbor 搜索框两层；不是所有页面都需要再加一个框。正文不增加卡片或分区框。
- Accounts 在窄屏会将六个按钮堆成六行，再加两行说明，占至少八行。应把顶层动作控制在一至两行，键位一行；其余保留键盘可达的 More/Help。
- Sessions 80×24 的合成全屏布局，固定 chrome 已占 9/24 行；真实 popup 更窄时导航换行进一步挤压。优先减少三行搜索框、两行重复提示和空 attention 行，不减少会话身份信息。
- 目录路径在一个选中项场景显示两次，来源还串成 `form directory / current pane / launch...`。合并来源为次信息，完整路径只在选中摘要显示一次。
- Profile `Current:` 与行内 `selected` 都表示已应用 Profile；列表的 `›` 则表示当前考虑项。应改成作用明确的 Current 标签与行选中背景，不用三种词/标记混叫“选中”。
- `●` 在所有会话状态行重复，不应再追加额外状态图标；保留状态文字与语义色。选择箭头和选中背景保留，前者保证无颜色可识别。
